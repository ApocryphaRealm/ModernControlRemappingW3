      // ================================================================================================================
      // Unbind Vanilla Controls - CONTROLLER ROWS under the controller diagram (Settings > Controller Scheme).
      // One row per control used in the tab on show; the script sends every row through "ingamemenu.uvc.padrows"
      // (label, the pad key it has, its tag and a bit per tab it belongs to). Up/Down (D-pad, left stick, right stick)
      // choose a row; A starts a change and the next pad button is the new key; Start or Esc cancels a change.
      // UNBIND = A, then the button the row already has (the owner, 2026-10-14: "if you select the same button that's
      // already bound to it, it should unbind it"). It is the row's off switch in the tab on show (9000 + tab), never a
      // cleared binding: the game cannot write a pad button over IK_None, so a truly cleared row could never be bound
      // again (2026-10-06). The row then shows "-"; A and ANY button binds it again - the switch goes back on, and a new
      // button is written over the binding it kept. Rows without an off switch (controls the game does not handle one by
      // one) cannot be unbound: the same button changes nothing there. A row whose control has no Xbox button in the
      // game's mapping comes marked "locked": dim, and A does not open it. The change goes to the script's
      // OnChangeKeybind with the row's tag; the script answers with the rows again, and the changed row is drawn in gold.
      //
      // Placement (1.0.0's first run put the list under the module's full bounds, which reach the bottom of the screen
      // through elements the diagram does not show): the list is a child of the MENU, placed at fixed parts of the
      // screen (UVC_LIST_TOP..UVC_LIST_BOTTOM of its height), and the page is scaled so the VISIBLE diagram ends above it.
      // ================================================================================================================
